# 图灵完备 · 二进制速算 / 负数 自动答题机器人

**中文** | [English](README.en.md)

> Automates the **Binary Racer** and **Negative numbers (signed binary)** minigames of
> *Turing Complete* by reading the screen and injecting real mouse clicks.
> Measured result: full clear with zero wrong answers (**63/63** unsigned, **53/53** signed).

> 通过屏幕识别与真实鼠标点击,自动完成《图灵完备》「二进制速算」与「负数(有符号二进制)」小游戏

通过屏幕像素识别 + 真实鼠标点击,自动完成《图灵完备》里「二进制速算」和「负数(有符号二进制)」两个小游戏:
读题 → 计算点亮哪些位 → 点芯片 → **校验求和** → 提交 → 记录题目/题号/用时/结果。

## 原理

游戏是自研 GLFW/OpenGL 引擎(不是 Unity),无障碍树为空、后台截图全黑,所以走"可见像素 + 真实点击"路线:

| 环节 | 做法 |
| --- | --- |
| 取帧 | DPI 感知截屏,只截**游戏窗口矩形**并缩放到固定"帧空间"(1568×980);窗口不是全屏也能正确工作 |
| 识别 | 用游戏自带字体离线渲染候选数字,与屏幕上的橙色字形做归一化互相关(NCC),真实题命中 0.86–0.99;首位宽扁字形判为负号 |
| 定位 | 8 个位芯片按"等距同排圆形"刚性几何校验,其它界面一律判为 unknown,**绝不盲点** |
| 求解 | 目标值 `v` → 点亮满足 `v & bit` 的位(Python 负数天然补码,所以无符号/有符号同一行代码) |
| 校验 | 提交前:①8 颗芯片状态与目标一致 ②游戏若显示"= 求和",读数必须等于目标(高关卡游戏会隐藏求和,此时以芯片状态为准) |
| 状态机 | ready / question / 弹窗 / unknown;弹窗按红色关闭钮或蓝色标题栏识别,自动点「继续」 |

## 环境要求

- Windows 10/11,Python 3.9+(实测 3.11)
- `pip install pillow numpy opencv-python`
- 游戏 *Turing Complete* 已安装(Steam),建议无边框全屏(实测 2560×1600,其它分辨率自适应)
- **字体**:程序自动从 Steam 库探测游戏的 `asset/font/NoroshiCode_Bold.ttf`;
  也可用环境变量 `TC_BINRACER_FONT` 或 `--font <路径>` 指定。仓库**不包含**任何游戏资源。

## 快速开始

```bat
pip install pillow numpy opencv-python
:: 打开游戏 → 进入关卡 → 停在「准备好了吗? / 开始」界面,然后双击:
run_standalone.bat
```

运行期间**不要操作鼠标**;控制台会最小化到任务栏(悬停图标可看答题进度),按 **F12** 可随时中止。

## 命令行参数

| 参数 | 说明 |
| --- | --- |
| `--input {sendinput,file}` | `sendinput`=自己进程注入真实鼠标(默认推荐);`file`=把点击交给外部代理执行 |
| `--capture {screen,file}` | 取帧方式(与 `--input=file` 配合可支持被遮挡时取帧) |
| `--ipc-dir DIR` | `--input=file` 时的请求/应答目录 |
| `--max-seconds N` | 单次运行时长上限(默认 480) |
| `--lost-seconds N` | 游戏画面持续无法识别多久后安全停止(默认 8) |
| `--save-shots` | 每题保存题目/芯片截图 |
| `--font PATH` | 指定游戏字体 |
| `--log-file PATH` | 把输出同时写文件 |
| `--no-console-min` | 不自动最小化控制台 |

## 记录输出

每次运行一个目录 `logs/run_<时间戳>/`:

| 字段 | 含义 |
| --- | --- |
| `q_index` | 题号(本局第几题) |
| `target` | 识别出的题目数字(可为负) |
| `bits` | 点亮的位,如 `128 + 64 + 16 + 1` |
| `submitted_sum` | 提交时游戏显示的求和读数(高关卡隐藏时为"-") |
| `verify_ok` | 提交前校验是否通过 |
| `target_score` / `target_margin` | 识别置信度 / 与次优候选的差距 |
| `elapsed_ms` | 本题用时 |
| `clicks` | 本题点击次数 |
| `result` | accepted / pending / unknown 等 |

另有 `questions.jsonl`、`shots/`(每题截图)、`summary.md`、`DONE.json`(结束原因)。

## 稳定性设计(踩过的坑)

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 重复点击导致答错 | 点完立刻读帧,游戏还没渲染完 → 误判漏点 → 把已对的位又点一次 | 点后 `settle()` 等状态稳定再判;同一位置 200ms 去抖 |
| 提交丢失后重复解题 | 提交点击被吞时程序会重解同一题 | `pending_sig` 守卫:同一题且芯片已正确时只等待,最多补按一次提交 |
| 过渡帧把整局判死 | 题号刚消失/纯背景帧被当成"读数冲突" | 三取二多数表决;真不一致就等待游戏自己走,不再结束整局 |
| 点击整体偏移 | 假设"游戏一定全屏铺在 (0,0)" | 按窗口真实矩形换算截图区域与点击坐标 |
| 坐标偏 1.5 倍 | 进程以"非 DPI 感知"启动后再也改不回来 | 模块导入时即设置 DPI 感知 |
| 窗口被改成非全屏 | 早期版本调用了 `ShowWindow(SW_RESTORE)` | 已移除,绝不改动游戏窗口显示状态;异常时启动横幅提示 |

## 已知限制

- 两个小游戏打满(二进制速算第 7 级 / 负数第 6 级)后游戏会结算并回到关卡树,需手动重进关卡。
- 高关卡游戏会隐藏"= 求和",校验退化为芯片状态校验(仍保证正确)。
- 屏幕被遮挡且未启用外部取帧代理时,程序会安全停止而不是乱点。
